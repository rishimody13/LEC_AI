Reconcile inventory when partial returns contain conflicting metadata
Build an agent that processes partial stock returns where the returned items carry embedded metadata (batch codes, expiry dates, condition notes) that may contradict the warehouse system of record. The agent must decide whether to trust the physical evidence on the returned items, query external sources to arbitrate, or flag the return for manual review. It must then correctly reassign the stock to inventory bins without introducing data drift: if it makes the wrong choice about which batch a returned item belongs to, downstream forecasting and allocation will fail silently. The agent should handle at least two independent failure modes: metadata that is unreadable or corrupted, and metadata that is internally consistent but conflicts with multiple plausible warehouse records. Ship a working implementation that demonstrates the agent making a non-trivial decision under uncertainty, with a three-minute video showing it processing a return where the obvious choice is wrong.

Requirements

Implement an agent that makes at least two sequential decisions about a single return: first, whether to trust embedded metadata or system records; second, which inventory bin to reassign the stock to based on that decision. The agent must choose between genuinely competing strategies at runtime, not execute a fixed sequence.
Handle two independently failing components that interact: one that reads and validates physical metadata (simulated or real), and one that queries warehouse records. When both fail or conflict, the agent must reason about which failure is more likely and act accordingly, with no fallback to a default choice.
Demonstrate that the agent's decision affects downstream correctness: show that assigning returned stock to the wrong batch or expiry window would cause measurable harm (e.g., incorrect stock-out predictions, or items shipped past their best-before date). The submission must prove this harm is real, not hypothetical.
